# CraftEngine 桌游显示适配设计

日期：2026-10-02。基线：`1.8.7-SNAPSHOT`，提交 `c31059d`。

状态：书面设计，待用户审阅；尚未修改游戏代码或制作资源包。

## 1. 目标与范围

按用户提供的四项要求，为麻将和 Color Eight 增加资源包显示，同时保留原版显示。混合模式允许同一桌玩家使用不同显示方式；附近没有原版观看者时，应实际删除原版显示实体，降低服务端实体数量。资源包提供精细牌面、桌体、麻将桌布和对局音效。

本批适配麻将及 Color Eight 的牌、桌体、相关按钮和装饰；其他游戏暂时维持现有原版显示。菜单上的个人开关控制这一份桌游资源包，不改变其他游戏规则。这个范围是根据本次指定的两款游戏作出的实施假设。

保留已经认可的行为：手牌私有、同牌高亮、不可出牌降低亮度、摸牌暂不挤动原手牌、Color Eight 从左到右斜叠及轻微悬停抬升、四色按钮不带数字、选色后的彩8以对应颜色为底、麻将私人宝牌指示器、宝牌附魔效果、Shift 固定观察镜头及退出恢复。

只做本地交付。源素材留出处与摘要；不发布 Release，不替换运行中的服务器 JAR。

## 2. 三种模式及失败处理

插件 `config.yml` 增加 `rendering.mode`：

| 值 | 行为 | 菜单开关 |
|---|---|---|
| `vanilla` | 麻将、Color Eight 使用优化后的原版显示 | 无 |
| `resource-pack` | 进入这两款游戏前请求桌游包；加载成功才允许参与 | 无 |
| `mixed` | 玩家自行选择；成功加载后才使用资源包显示 | 顶部显示 |

默认 `vanilla`，已有服务器升级后保留原版体验。模式变更通过重启应用，避免在进行中的房间批量重建实体。包的 URL、SHA-1 和固定 UUID 位于 `rendering.resource-pack`，UUID 只标识桌游包。

混合模式中，新玩家默认原版，选择按 UUID 持久化。菜单开关显示“启用桌游资源包”“加载中”“关闭桌游资源包”等实际状态；切换后刷新当前菜单。纯模式不添加占位按钮。

“用户希望启用”与“客户端已成功加载”是两个不同状态。拒绝、下载失败、加载失败或失效不能使客户端看到无纹理的模型：

- 混合模式继续原版显示，说明失败并允许重试。
- 纯资源包模式保留菜单和重试入口，不允许加入、恢复操作或开始这两款游戏。已在对局中的玩家加载失效后保留座位，按现有离线/超时机制处理；不自动出牌，不踢出服务器。
- CraftEngine 缺失或配置未就绪：原版模式正常运行；混合模式暂不可启用资源包；纯资源包模式不能开始受影响的游戏，并给出管理员可定位的原因。

对过期加载结果、重复点击及退出后的回调进行校验。关闭时立即恢复原版显示，并仅移除桌游包自己的 UUID。

## 3. 独立资源包与 CraftEngine 分工

采用“独立 ZIP + CraftEngine 自定义物品注册 + 插件按玩家切换 ItemDisplay”的方式。

资源全部使用 `tabletop3d` 命名空间，提供自己的现代物品模型定义，不覆盖其他包的物品、字体或原版音效。包包含牌面、牌背、桌体、桌布、按钮、音效和 `pack.mcmeta`。

CraftEngine 扩展目录注册这些自定义物品，插件从注册表取得物品栈作为显示模型。资源包是一份已经构建好的独立 ZIP，不依赖 CraftEngine 全量生成步骤来隔离内容。安装文档提供独立包托管的配置片段；管理员可使用 CraftEngine 托管，也可填写独立静态地址。

由桌游插件统一发送和移除自己的包，通过 Paper 的资源包 UUID 和加载状态事件确认结果。CraftEngine 中这一独立包不设置自动发送，避免两个发送流程重复管理同一包；也不使用会改变其他资源包选择的 preset 命令。现有 CraftEngine 主包及其他插件的包继续使用自己的配置。

交付包括安装位置、配置合并示例、URL/摘要填写方式和更新流程。配置片段不能整文件覆盖用户已有的 CraftEngine 配置。

## 4. 混合显示与实体生命周期

规则状态、牌 ID、排序、坐标、点击区域和动画时序由同一份游戏状态驱动；显示模型的多少不能改变点击结果。

每张资源包牌的牌身、正面和背面合在一个模型中，用一个 ItemDisplay 显示；高亮使用实体发光，灰牌修改亮度，宝牌使用物品附魔流光，不重复铺设花纹实体。

公开部分按需要维护原版与资源包两套显示，但每位玩家只收到自己的那套：

- 有原版观看者时，创建并显示原版公开实体。
- 有已加载资源包的观看者时，创建并显示资源包公开实体。
- 对应观看者数量归零时，移除该套实体，不只隐藏。
- 玩家首次进入范围、改变显示方式、跨世界、退出、房间结束及插件关闭时，更新并清理对应实体。

“观看者”包括同世界、桌面显示有效范围内的玩家及旁观者，不只统计四/五个座位。范围要覆盖当前实体的实际可见距离，避免远处原版旁观者看到空桌；使用附近玩家集合，不能每 tick 对每张牌扫描全服玩家。

私有手牌仅为对应玩家创建一套正面显示。其他人只看到该座位的公开牌背。两套实体先设为默认不可见，再向已确认的观看者开放；切换过程中不出现一帧漏牌。私人宝牌指示器、吃碰预览及选择按钮遵循同样规则。

移除某种显示后仍保留轻量的逻辑牌位数据，点击检测不能依赖被删除的原版实体列表。静止实体不持续传送；只更新动画中或实际发生变化的内容。

## 5. 原版模型优化

优先精简当前重复较多的圆角、筒子圆环、牌背装饰和圆桌分段。合并可以合并的平面，减少被其他部分完全遮住的单元；保持辨识用的外轮廓、颜色、笔画、圆角及数字 6/9 标记。

不能通过缩小牌、删掉重要花纹或把圆桌改成方桌达到数量下降。优化前后生成相同牌面、相同桌面布局的对照预览，并更新逐牌及整桌实体统计。统计同时区分服务端存活实体与单个玩家可见实体，不把减少数量直接宣称为 FPS 提升。

Color Eight 的方向提示保留方向辨识，减少组成实体及无必要更新。卡牌叠放、悬停幅度和选色操作沿用当前认可的方式。

## 6. 麻将中央面板

按照本次四张图片，将黑色中央板扩大为带层次边框的方形面板，初始宽度约 1.10 格；对照现有 3×3 桌面和六张一排的牌河检查间距，不能遮挡弃牌或手牌。

- 取消玩家身后的分数，把规则引擎的实际分数放在中央面板四边。
- 保留四个方位标记和庄家提示；四边分数分别朝向对应座位。
- 中央显示局数/场风与剩余牌数，字号比现在大。
- 中央文字为按观看者定向的私有标签：有座位的玩家按自己的座位方向阅读；旁观者按最近的桌边方向阅读，跨桌边时再更新，不每 tick 跟随转头。
- 余牌为 0 时，数字变红。
- 当前行动方用边缘提示识别，避免在中央堆叠四份公共文字。
- 立直棒放在相邻方位之间的预留位置，保持已经加长的长度和红点。

原版和资源包模式使用同一布局及数据。资源包模式用精细面板模型，原版用较少的方块单元。桌布只出现在资源包显示中，不能覆盖原版玩家看到的桌面。

已有高处倒计时与必要操作提示保留；把分数移入中央面板不改变对局、结算或计分规则。

## 7. Color Eight 资源包外观

沿用已认可的 B 版语言，制作更清晰的牌面纹理：圆角米白边框、明确色底、数字与功能图案、大字号主图和角标。对多牌斜叠时露出的部分检查辨识度；精细度服务于看牌，不堆叠细小装饰。

牌身使用薄的圆角几何，部分装饰允许旋转角度。四色按钮只显示颜色与辨识图形，不写 8；点击后桌上彩8使用所选颜色底的 8。牌背、抽一张、跳过、反转、交换及 6/9 区别保持一致。

圆桌使用少量模型表达更圆的轮廓；不能将整桌手牌烘在同一个模型中，以免失去私有显示、单牌高亮和独立交互。

## 8. 麻将图片与声音

从用户指定的素材目录选取默认牌面图集、默认桌布及少量对局音效，先核对牌面映射再裁切，不下载整个游戏资源档案。

音效按实际事件播放，包括选牌、打牌、吃碰、副露、杠、宝牌翻开、立直、和牌及倒计时；先核对声音内容，不凭文件名映射。只提供本批对局所需内容，不附带整套音乐或角色语音。文件转换为 Minecraft 可用的 OGG，记录来源、原始摘要、转换方式和最终摘要。

资源包玩家听自定义音效，原版玩家听现有原版音效；采用按玩家发送，避免同一事件同时播放两种声音。沿用现有 `sounds.enabled` 和音量配置。桌布、牌面及音效分别有预览/试听样本供验收。

## 9. 验证与交付标准

1. 三种模式、菜单开关、偏好持久化、失败回退、过期加载回调及 CraftEngine 缺失行为有自动化覆盖。
2. 原版与资源包玩家同时在桌边时，分别只收到相应显示；旁观者也计入。最后一位原版观看者离开后，原版实体实际删除，回来后重建。私人牌面、宝牌和预览不泄漏。
3. 牌位、点击区域、吃碰按钮、彩8选色、动画及现有 Shift 固定镜头不因切换显示方式改变。
4. 检查全部模型/纹理/声音引用、图集映射、音频编码、ZIP 根目录和摘要；独立包不覆盖其他命名空间。
5. 中央面板四个座位方向、四边分数、立直棒位置、0 张红字及桌布显示分别核验。
6. 按现有基线场景对比逐牌、整桌服务端和每人可见实体数量，记录混合与全资源包场景。客户端 FPS、实际流光、视角和声音效果需要 Minecraft 客户端验收，不能由服务端探针代替。
7. 本地交付新 JAR、独立资源包 ZIP、CraftEngine 物品配置、托管配置片段、安装说明、素材出处、外观对照和测试/实体统计证据。自动化验证与客户端待验项目分开说明。
