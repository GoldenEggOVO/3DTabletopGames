# 以 1.8.10 测试版为基准整理桌游插件

状态：用户已批准全部实施（2026-10-02），并增加有色麻将牌背、横牌布局及移除 AuthMe、Geyser/Floodgate 接口。

## 目标与范围

用户要求：日麻立直后自动出牌，出现和牌按钮时由玩家决定；Color Eight 增加玩家回合指示；清理不再需要的旧版适配与难懂命名，简化实现，保持现有使用体验。

仅修改 3DTabletopGames。Casino 只作为命名、翻译和职责划分参考。基准为实际部署的 1.8.10-SNAPSHOT，源代码提交 faea2aa，Paper/Purpur 26.2、Java 25、CraftEngine 26.8.2。

保留目前的游戏规则、菜单入口、实体外观、卡牌朝向、手牌遮挡与高亮、Ctrl 看桌、Shift 右键菜单、三种渲染模式、资源包加载选择、房间恢复、语言热重载与权限行为。

本次明确允许整理翻译文件，取代上一轮“先不要更改”的限制。保留自定义译文和菜单内容，通过单独的转换步骤处理已有文件。

## 现状证据

- en_US.yml 与 zh_CN.yml 各有 947 个键，其中 374 个带六位哈希后缀。
- Language.java 同时承担按键取值、短语正则替换、旧文件迁移和模板适配，规则层仍返回需要再次拼接翻译的展示字符串。
- Tabletop3D.java 的 327 行中有 45 行超过 180 字符，混合了动作执行、周期任务、存档写入和恢复。
- GameMenus.java 的 296 行中有 29 行超过 180 字符。HandTable.java 为 691 行，混合公开牌、私有牌、动作按钮与资源包实体构建。
- GameMenuLayouts.java 每次加载都会计算旧模板摘要并替换历史默认样式。
- 正常启动仍尝试从 ServerBoards 复制数据，并支持 lang、translations、messages 的旧语言格式。
- Color Eight 仍以 LastCardGame 和 lastcard 命名；旧罚抽 finish 选项会被忽略，回放中有旧牌堆耗尽后的 draw/pass 特殊分支。
- CraftEngine、AuthMe、Geyser/Floodgate 的反射调用是当前可选集成，并非可直接删除的旧版兼容。

## 方案选择

1. **推荐：按功能分步整理。** 先增加两个功能，再整理翻译和明确失效的兼容逻辑，最后拆分主要职责。每一步都有行为检查和可对比的产物。
2. 仅重命名和格式化：改动小，但仍保留短语翻译与多重迁移，无法满足这次整理目标。
3. 重写所有规则与渲染：范围大，会重新引入布局、回放与回合问题，当前证据不支持这样做。

## 日麻立直自动摸切

- 日麻已立直的真人玩家，在自己的普通摸牌回合自动打出刚摸到的牌，不选择手中其他牌。
- 通过同一条动作执行路径提交合法 discard，照常更新回合、历史、动画、音效和存档；不在规则 apply 中递归推进整局。
- 使用具名的短暂动画间隔，自动动作每次执行前核对房间、当前座位和 revision，避免重复执行或将过期动作用于下一轮。
- legalActions 包含 ron 或 tsumo 时停止自动动作，保留和牌按钮和玩家选择；普通真人超时处理不得越过这个等待状态。
- 玩家主动跳过荣和仍按现有振听规则处理；自摸提示的“跳过”明确表示放弃这次自摸，通过同一条合法 discard 动作打出刚摸到的牌并继续。这样无需保存独立的“忽略自摸”标记，也不会因 legalActions 仍含 tsumo 而再次暂停。
- 自动摸切不替玩家决定暗杠；本次按“持续自动出牌直到可和牌”实现，不额外增加暗杠暂停。暗杠合法性规则保留。
- 立直宣言牌仍由玩家选；宣言尚被他家荣和处理、换局、结算、暂停、离线保留或资源包未就绪时，不启动真人自动摸切。
- 自摸、荣和、流局、换局和恢复均重新计算自动状态，无需额外持久化第二份规则状态。

## Color Eight 回合指示

- 当前玩家手牌附近显示绿色短条与玩家名字；随当前座位变化，反转和跳过后定位到实际行动者。
- 原版和资源包都显示相同提示，覆盖 2–5 人布局，不遮挡手牌、颜色选择按钮或桌面牌。
- 等候、结束和暂停时取消活动提示。回合方向箭头继续表达方向，不与活动玩家提示混用。
- 只在状态变化时更新；不为每张牌增加提示实体。

## 翻译系统

- 继续使用 languages/en_US.yml、zh_CN.yml，维持 Casino 的独立语义键与具名占位符方式。
- 按公共菜单、房间、各游戏、错误、资源包与桌面提示排列，加章节注释；不使用随机数字或哈希后缀命名。
- 动态描述使用完整模板，例如 ludo.move、mahjong.result、color-eight.turn，参数使用 player、piece、count 等名字，不把句子拆成“玩家”“移动了”“个”等片段。
- 规则返回稳定原因／状态标识及参数，展示层负责翻译；玩家名字作为字面 Component 插入，不能被短语替换或解释为格式标签。
- 热重载、英文回退、占位符校验和失败时保留上一份正确语言保持现有行为。
- 使用独立转换工具迁移 1.8.10 的语义键和哈希键。先保存原文件，输出转换报告；保留未知自定义值用于人工核对，不静默丢弃译文。
- 句子重组时不能机械拼接旧译文；完整的新模板明确写出，旧自定义片段在转换报告中指出对应模板。
- 完成转换后移除 Language 中的短语正则替换、ALIASES/SOURCES 适配、language-compatibility.yml，以及运行时旧目录迁移。正常启动只读取当前格式。

## 命名、兼容和职责

- Java 类使用 ColorEightGame 等实际玩法名称；游戏注册、命令、模型清单使用明确名字。
- 牌值、棋盘坐标、座位编号、UUID 和回调 token 保留各自意义，不因它们包含数字就改成不稳定展示名称。
- 当前存档的 lastcard 类型由转换工具转为明确的规范游戏 ID；牌 ID、动作参数、随机种子、座位和历史顺序保持不变。
- 从正常运行中删除旧 ServerBoards 复制、lang 迁移、旧菜单摘要／旧固定标签自动升级、旧 Last Card 规则历史处理和已经取消的 finish 选项适配。
- 对当前基准存档逐局回放。若它含有旧版耗尽牌堆的 draw/pass 历史，必须先证明转换前后状态、回合和手牌一致；不能直接删兼容后把现有房间变成无法恢复。
- 当前合法记录仍做 schema、rulesVersion、座位及动作校验；保留原子保存、恢复预算和世界归属校验。这些保护承担当前数据正确性。
- 保留 CraftEngine 可选桥接；依用户最新要求移除 AuthMe、Geyser/Floodgate 桥接及插件自行判断登录状态、基岩版客户端的分支。权限和在线检查保留。
- 将房间序列化与恢复移入 RoomStore，将自动动作／普通超时策略移入清晰的回合策略类。主插件负责生命周期和调用顺序。
- 菜单回调、动作应用和展示更新展开为短方法，变量使用 room、seat、action、piece 等明确名字。
- 手牌渲染仅在具有单一职责的边界拆分公开牌、私有牌和动作控件；不引入统一所有游戏的大框架，也不重写第三方棋类算法。

## 有证据的优化

- 清除短语正则翻译链；避免每条显示文本扫描整份翻译表。
- 清除每次菜单打开时的历史模板 SHA-256 计算。
- 回合策略在同一状态下复用合法动作，不反复计算整副日麻手牌。
- 继续按 revision 和观众模式更新显示；改善查询和对象构建，但保持点击时重新校验动作与房间 revision。
- 保存优化以减少重复写入为目标，维持离线、离开、停服和已接受动作的恢复保证。未证明恢复边界一致前不改变保存频率。
- 不承诺未经客户端测量的 FPS 提升；记录相同场景的实体数量与更新次数，避免整理导致增加。

## 验收

1. 自动摸切：立直后只丢刚摸到的牌；荣和和自摸都暂停；跳过后继续；过期回调、重启恢复和换局不重复出牌；其他麻将规则不受影响。
2. Color Eight：2–5 人、反转、跳过、换手、彩 8 选颜色、结束和暂停的指示一致；两个渲染模式可见。
3. 翻译：两份目录键和占位符一致、没有哈希键或孤立短语，所有展示路径可单独翻译；保留自定义菜单和可转换译文，字面玩家名不变。
4. 数据：备份 1.8.10 数据，转换后恢复相同房间、选项、座位、手牌、历史、当前玩家和结果；恢复规则版本正确。
5. 全部现有有效行为回归通过；删除仅针对被取消的旧格式测试，不能删掉失败测试以掩盖当前行为变化。
6. 重新执行原版和 CraftEngine 启动、恢复和资源包验证，产出独立交付包与报告。
7. 按既有授权备份并更新独立测试服；部署前明确提示停服，保留全部现有玩家数据。游戏内视觉、声音和操作感单独验收，不发布 Release。

## 建议执行顺序

两个功能及回归 → 翻译与状态表达 → 当前数据转换与兼容清理 → 房间／菜单／渲染职责整理 → 相同场景核验 → 测试服更新。

每步保持可构建，以最终通过全部验收的版本为交付对象。
